# Review record schema

Return one fenced YAML block followed by no additional prose.

```yaml
review_type: design
status: approved
reviewed_files:
  - path: docs/simulators/example/tasks/T1-1/DESIGN.md
    hash: sha256:<64 lowercase hexadecimal characters>
findings: []
conditions: []
rollback_to: none
summary: <short evidence-based conclusion>
```

Allowed values:

- `review_type`: `design`, `testcases`, `test-code`, `implementation`
- `status`: `approved`, `changes-requested`, `needs-human`
- `rollback_to`: `design`, `testcases`, `test-code`, `implementation`, `none`

For findings, use objects with stable identifiers:

```yaml
findings:
  - id: R-001
    severity: critical
    location: path/to/file.ts:42
    problem: <observable defect or risk>
    evidence: <why this is a defect>
    required_change: <smallest acceptable correction>
```

Allowed severity values are `critical`, `high`, `medium`, and `low`. Approval
requires no unresolved finding. Do not use conditional approval; unresolved
conditions require `changes-requested`.

Paths are repository-relative. Hash values are SHA-256 over the exact file bytes
and can be generated by `scripts/hash-files.mjs`.
