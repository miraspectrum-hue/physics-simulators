## 既存8案の評価

### 1. 水面の波紋と光の干渉（波動）
- **物理的根拠**: 円形波の重ね合わせ `h(x,y,t) = Σ A/r・cos(kr - ωt)`。二重スリットの
  強め合い条件は経路差 `= mλ`。高校物理必修範囲。
- **知名度**: ◎（水槽実験はテレビ・教科書の定番）
- **操作アイディア**: クリックで波源を配置、スリット付き障害物をドラッグで配置・移動
- **表現アイディア**: 平面メッシュの頂点変位＋法線ベースのシェーディング（水面シェーダ）
- **実装の勘所**: 波源数×グリッド解像度の計算量が課題。フラグメントシェーダで高速化しやすい
- **評価**: 操作性◎ 見た目◎ 知名度◎ 難易度: 中

### 2. 磁力線と砂鉄のパーティクルアート（電磁気学） ※設計検討済み
- **知名度**: ◎（小学校理科の定番実験）

#### 見せ方: 3Dシーン＋2Dの砂鉄平面（ハイブリッド）

**3Dを推すが、砂鉄自体は平面上に乗せる。**

- あの実験の記憶は「紙を真上から見た平面の絵」である。完全な3D空間に砂鉄を浮かべると誰も
  見たことのない絵になり、**知名度という最大の強みを捨ててしまう**
- 一方で磁場は本来3次元であり、紙の上を通る磁力線は2Dスライスには写らない
- 折衷案: シーンは3D（OrbitControlsで傾けられる）、磁石は3Dオブジェクトとして紙の上／下に
  ドラッグ配置、砂鉄は平面上の2Dシミュレーション。真上から見れば教科書の写真そのもので、
  傾ければ3次元構造が見える
- **紙の高さ（スライス位置）をドラッグで上下できる**ようにすると、高さによる模様の変化が
  見える。実際の教室では不可能な、シミュレータならではの体験になる
- **表示モードのトグル**を用意する
  - **砂鉄モード**（本命） … 平面上の数万粒子
  - **磁力線モード** … シード点からRK4で磁力線を空間に積分し3Dのラインで描く。prism-sim の
    `optics/tracer.ts`（純粋関数で経路を返す）＋ `scene/BeamRenderer.ts` がほぼそのまま転用可
  - **|B|ヒートマップ** … 平面上の磁束密度の強さを色で表示

#### 磁石のモデルとパラメータ

- **磁荷モデル（±の磁荷ペア）を採用する**。点双極子の式 `B ∝ [3(m·r̂)r̂ - m]/r³` は遠方では
  正しいが、砂鉄写真を支配するのは磁石近傍の場であり、そこでは形が合わない。棒磁石の両端に
  ±qm を置きクーロン型の場 `B = (μ0·qm/4π)·r̂/r²` を重ね合わせると、近距離まで良く合ううえに
  閉じた式で軽く、U字磁石も磁荷の配置換えだけで表せる
- **要SPEC明記**: 磁気単極子は実在しない。これは一様磁化した棒の磁化を等価な磁荷で記述する
  数学的な道具であり、**磁石の外部でのみ妥当**である旨を明記する

| 磁石ごとのパラメータ | 操作方法 |
|---|---|
| 位置 | シーン内でドラッグ（紙の上／下も選べる） |
| 向き・回転 | 回転ハンドルでドラッグ |
| 磁力の強さ（磁荷量 qm） | スライダー、または磁石のサイズに連動 |
| 種類 | 棒磁石／U字磁石／円盤磁石をパレットからドラッグ&ドロップ |
| 極性反転 | クリックでN/S入れ替え |

環境パラメータ（ControlPanel 側）

- 砂鉄の粒子数（数千〜数万）、粒子の長さ
- **摩擦（紙との静止摩擦）** … 高いとその場で向きだけ変わり、低いとサラサラ動いて極に集積する
- **「トントン叩く」ボタン** … 紙を叩くと摩擦が一瞬消えて粒子が再配置される。実験の必須手順
  そのもので体験としても気持ちよいため必ず入れたい
- 平面の高さ z（スライス位置）
- 地磁気のON/OFF（一様な水平磁場の重畳）… コンパスの原理につながり、実装は定数ベクトルの加算のみ

#### 砂鉄の挙動: トルクと勾配力の両方を入れる

- **トルク** … 砂鉄粒子は誘導双極子になり、長軸を局所的なBの向きへ揃える → 「磁力線の模様」を作る
- **勾配力** … `∇|B|²` に沿って磁場の強い方へ引かれる → **極のまわりに砂鉄がびっしり集まる**
  あの見え方を作る
- 片方だけでは写真の印象にならない。両方入れるのが正しく、かつ物理的にも正確
- **区別の明示**: 砂鉄は「磁力線を描いている」のではなく、個々がトルクで整列しているだけである。
  磁力線モードはあくまで可視化の補助線であり砂鉄モードとは別物、とUIで区別する

#### 実装の要点

- 磁場計算は純粋関数層（`magnetics/field.ts` の `fieldAt(magnets, point)` 等）に閉じ込め、
  Vitestで検証（遠方で双極子場に漸近するか、対称位置で対称か、単一磁石の軸上解析解と一致するか、
  湧き出しがないか）
- **性能**: 3万粒子 × 磁荷20個 × 60fps ≒ 3,600万回の評価はJSでは厳しい。対策は
  (a) 磁荷を uniform 配列でGPUへ渡し頂点シェーダで粒子を動かす（磁荷はせいぜい数十個なので
  uniformに収まる。最も素直で速い）、(b) 磁石が動いていないフレームは再計算しない
  （dirtyフラグ。prism-sim と同じ）
- **描画**: 砂鉄1粒＝短い線分として、数万本を1つの `LineSegments` に束ね**永続 `Float32Array`
  を書き換える**。prism-sim の `BeamRenderer` の手法（`setPositions()` は初回のみ、以降は
  `instanceStart.data.needsUpdate` を立てる、`frustumCulled = false`）がそのまま使える。
  **本案を上位に推す理由の大部分がこの転用性にある**
- 粒子の向きは180°の対称性を持つ（BでもーBでも見た目は同じ）ため、線分は粒子位置を中心に描く
- **要SPEC明記**: 実際の砂鉄は3次元的に積み重なるが、2D平面モデルでは重なりを扱わない

- **評価**: 操作性◎ 見た目◎ 知名度◎ 難易度: 中

### 3. 万有引力と惑星の軌道サンドボックス（天体力学）
- **物理的根拠**: 万有引力の法則、N体問題の数値積分（Velocity Verlet 等）
- **知名度**: ○（宇宙番組・理科で目にするが軌道力学自体の知名度は中程度）
- **操作アイディア**: 星をクリック配置、ドラッグで初速を与える（スリングショット操作）
- **表現アイディア**: 軌跡を発光する尾で描画、衝突・合体エフェクト
- **実装の勘所**: 近接遭遇時の数値不安定対策（ソフトニング等）が必要
- **評価**: 操作性◎ 見た目◎ 知名度○ 難易度: 中

### 4. 雪の結晶のフラクタル成長（気象学） ※再検討済み
- **物理的根拠**: 中谷ダイヤグラム（温度・過飽和度で結晶形態が変わる）。結晶形態は本質的に
  **2つの独立した軸**で決まると整理できる
  - **c軸／a軸の成長速度比（≒温度で決まる）** … 板状か柱状（角柱・針）かを決める
  - **枝分かれの有無（≒過飽和度で決まる）** … 単純な六角板か樹枝状かを決める。水蒸気の
    拡散不安定性によるもので、ここだけがセルオートマトン（Reiter / Gravner–Griffeath 等）
    の出番
- **知名度**: ◎（誰もが知る雪の結晶の形）

#### 操作性の再設計（旧: スライダー ○ → 新: ◎）

温度・湿度のスライダー2本は「触って楽しい」からは遠い。**中谷ダイヤグラムそのものを操作盤に
する**ことで、この案の最大の弱点を長所に変えられる。

- 画面に中谷ダイヤグラム（横軸=温度、縦軸=過飽和度、領域ごとに板状／針状／角柱／樹枝状を
  ラベル表示）を2Dパネルとして置き、**その上のマーカー1個をマウスでドラッグする**
- ドラッグしている間、結晶はリアルタイムに成長し続ける。**途中で領域をまたぐと、そこから先の
  成長だけが新しい形態になる**（六角板の外周から樹枝が伸び始める、など）
- これは物理的にも正しい見せ方である。実際の雪結晶は雲の中を落下しながら異なる温度・湿度の層を
  通過し、**その履歴が形として残る**。つまりユーザーは「結晶の落下軌跡をマウスで描いている」
  ことになり、ドラッグの速さ（＝その条件下での滞在時間）まで形に反映される
- 副次的な操作として、完成した結晶を **OrbitControls で回して眺める**、成長履歴を
  **タイムラインのドラッグで巻き戻す/早送りする**（軌跡が決定論的なので再生で実現できる）、
  作った結晶を並べて見比べる、などを足せば「触って楽しい」がさらに強化される

#### 実装方針の再検討

**前回の助言を一部撤回する。** 対称性の利用と GPGPU 化を推奨したが、規模を見積もり直すと
**どちらも初手では不要**である。

- **CPU・全格子で十分**: 200×200 の六角格子は 40,000 セル。1ステップの更新は近傍6セルの
  読み出しと数回の積和にすぎず、約 50 万演算/ステップ。成長ステップを 10〜20 回/秒に
  間引けば毎秒 1,000 万演算程度で、JS の `Float32Array` 演算として何の問題もない
- **したがって 1/6 セクター化はしない方がよい**（※理由を 2026-09-07 の裏取りで訂正）。
  当初は「全格子を回せば非対称性が自然に出る」「実際の雪結晶は気流中の回転で完全対称に
  ならない」と書いたが、**どちらも誤りだった**。正しくは次のとおり。
  - 6本の腕は、結晶が漂う間**同じ環境を共有する**ため歩調が揃う。近い対称性は、結晶が
    たどった条件の履歴が1本であることの**物理的な帰結**である
  - 一方で**腕どうしは情報をやりとりしない**（独立に成長する）ため、完全対称にはならない。
    実物の不揃いは大気条件の変動に由来し、実験室で条件を一定に保つとほぼ同一の結晶が得られる
  - よって、セクターをミラーして**完全対称を強制する**のは実在しない形を作ることになる。
    かつ、全格子を決定論的に回しただけでは対称性は崩れない —— **崩すにはゆらぎを入れる
    必要がある**（当初の「自然に出る」は成り立たない）
  - 詳細と出典は `docs/simulators/snow-crystal-sim/SPEC.md`「六回対称性の扱い」を参照
- prism-sim の CLAUDE.md にある「optics層の割り当てが 60fps に影響するかは測定し、**問題が
  出た場合にのみ**高速経路を追加する」という方針をそのまま適用する。対称性利用・GPGPU
  （`WebGLRenderTarget` の ping-pong、新規案 C. BZ反応と同じ基盤）は、実測で詰まったときの
  **保険**として扱う
- **成長ステップと描画フレームを分離する**（prism-sim の「光路再計算を dirty フラグで抑制」と
  同じ）。CAは 50〜100ms 間隔、カメラ操作の描画は 60fps を維持
- **描画は六角柱の `InstancedMesh` 1つ**。セルごとの厚み（c軸方向）と氷の濃度をインスタンス
  属性バッファに書き込んで `needsUpdate` を立てる。これで 2D の CA 結果が**そのまま3Dの立体**
  になり、ボリュームレンダリングのような重い手法は一切不要
  （`apps/prism-sim/CLAUDE.md` の「毎フレームでのジオメトリ再生成禁止」に合致）

#### 段階的な開発計画（prism-sim の TASKS.md 方式に合わせる）

1. **成長コア（純粋関数）＋ Vitest** — 六角格子の水蒸気拡散と凍結判定を、DOM・Three非依存の
   `step(state) => state` として実装。既知形態（単純六角板／樹枝状）が出ること、水蒸気の
   収支が保存することをテストする
2. **3D表示** — c軸/a軸の異方性から各セルの厚みを決め、`InstancedMesh` で立体化。
   OrbitControls で回せるようにする
3. **中谷ダイヤグラムUI＋ドラッグ操作** — マーカーの軌跡が成長パラメータに反映される配線
4. **仕上げ** — タイムラインのスクラブ、結晶の保存・並べて比較、氷の透明感・反射の表現

#### 未解決の論点（着手前に決めるべきこと）

- **(T, 過飽和度) → CAパラメータの対応付けに一次資料がない**。Reiter モデルのパラメータは
  温度・過飽和度そのものではないため、中谷ダイヤグラムに合わせる**校正が必要**になる。これは
  この案で唯一スケジュールを食いやすい部分であり、「この対応付けは中谷ダイヤグラムの形態領域に
  合わせた現象論的なフィッティングであり、第一原理から導いたものではない」と SPEC に明記する
  必要がある（黙って係数を決めると prism-sim が禁じる偽装になる）
- **2Dの平面CAでは針状・角柱を作れない**。ただし上記の2軸モデルなら、柱状側は CA ではなく
  「六角柱の c 軸方向への伸長」という単純な幾何で表現できるため、ダイヤグラム全域を扱える
- **中谷ダイヤグラムの領域境界の数値（各形態が現れる温度帯）は要検証**。本資料はWeb未検証の
  ため、実装前に一次資料（中谷宇吉郎の原著、小林禎作による後年の精密化など）で確認すること

- **評価**: 操作性◎（中谷ダイヤグラム上のドラッグを主操作にした場合） 見た目◎ 知名度◎
  難易度: 中（成長コアと描画は素直。CAパラメータの校正だけが時間を食いやすい）

### 5. 地形生成と水流のサンドボックス（地球科学・流体力学）
- **物理的根拠**: 高低差に沿った水流、粒子ベースの水力侵食アルゴリズム
- **知名度**: ○（地学の単元、砂場遊びに近い直感）
- **操作アイディア**: なぞって山・谷を作る、「雨を降らせる」ボタン
- **表現アイディア**: 標高に応じた色分け（緑→茶→白）、水たまりの青
- **実装の勘所**: 侵食シミュレーション＋3D地形描画＋水面表現の統合はボリュームが大きい
- **評価**: 操作性◎ 見た目◎ 知名度○ 難易度: 高

### 6. 炎色反応の3D焚き火シミュレーション（化学）
- **物理的根拠**: 金属イオンの炎色反応（Li赤・Na黄・Cu緑・Sr紅・K紫等）。厳密には発光線
  スペクトルだが、可視化では波長→sRGB変換（`optics/spectrum.ts` 的手法）で根拠を持たせられる
- **知名度**: ◎（中学理科の語呂合わせ「リアカー無きK村…」）
- **操作アイディア**: 物質をドラッグ&ドロップで炎に投げ入れる、複数物質の混合
- **表現アイディア**: ノイズベースの炎パーティクル/シェーダ、物質ごとの発光色
- **実装の勘所**: リアルな炎のVFXは技術難度が高いが、**炎を「形（運動）」と「色（発光
  スペクトル）」に分離し、物理的厳密性の対象を色に限定する**と現実的なコストに収まる。
  prism-sim の規約が禁じているのは「主題の偽装」であって、すべてをPDEで解くことではない
  - **色（ここは物理計算で出す）**
    - 下地の橙〜黄はすす粒子の熱放射なので**プランクの法則（黒体放射）**から求める。
      温度T→スペクトル分布→CIE等色関数→sRGB という変換は prism-sim の `optics/spectrum.ts`
      と同じ設計で書ける（温度上昇で青白くなる色温度も自動的に出る）
    - 炎色反応は**各元素の主要輝線（波長nm＋相対強度）のテーブル**として持ち、上のスペクトル
      分布に加算してから同じλ→sRGB変換に通す。これにより**複数物質を混ぜたときの色が加法
      混色の帰結として自動的に決まる**（色を手打ちしないので「見た目だけの偽装」に陥らない）
    - スペクトル積分はCPU側の純粋関数層で行い、物質投入時のみ小さなLUT/uniformに焼いて
      シェーダへ渡す（毎フレームの分光計算を避ける）
    - **要注意**: Kの主輝線は766/770nmで可視域のほぼ端にあり、素直に実装すると「カリウムが
      ほぼ見えない」結果になる。教科書の「紫」はコバルトガラス越しの観察が絡む。これは
      prism-sim の「ダイヤモンドで虹が出ないのは物理的に正しい」と同種の論点なので、SPEC
      段階で扱いを決めて明記すること（波長値自体も一次情報での確認が必要）
  - **形（現象論モデルと割り切る）**
    - **curl noise（発散ゼロのノイズ場）ベースのGPUパーティクル**が本命。3Dノイズのポテン
      シャル場の回転を取るため非圧縮＝流体らしい渦が出る割に流体ソルバー不要で、頂点シェーダ
      内で完結する。CPU側は毎フレーム何もしない（永続バッファのみ）ので
      `apps/prism-sim/CLAUDE.md` の「レンダーループ内で `new` しない」規約と素直に合う
    - 代替案として**ボリュームレイマーチング**（FBM＋ドメインワープを上方向スクロール）。
      各marchステップで発光を積算する構造が「温度Tのガス塊が輝線を放つ」物理と対応が良い
    - **Navier-Stokes（Stable Fluids＋浮力項＋渦度閉じ込め）は過剰**。炎の形はこのアプリの
      主題ではないためコスト対効果が合わない
    - 仕上げは **HDR＋Bloom＋加算合成**（`AdditiveBlending` / `depthWrite: false`）。three
      本体同梱の `EffectComposer` / `UnrealBloomPass` で足りるためCDN不要で、prism-sim でも
      composer の実績がある
  - **SPECでの線引き**: 「炎の形状は現象論モデルであり、物理的厳密性の対象は発光色である」
    ことを明記する
- **評価**: 操作性○ 見た目◎ 知名度◎ 難易度: 中（形を現象論モデルと割り切る前提。厳密な
  流体解法まで求めると高）

### 7. 生物の群れ（Boids）と生態系モデル（複雑系科学）
- **物理的根拠**: Craig Reynolds の Boids アルゴリズム（分離・整列・結合の3ルール）。
  物理法則というよりアルゴリズム的モデル
- **知名度**: ○（群れの映像自体は身近だが「Boids」という仕組みの知名度は高くない）
- **操作アイディア**: クリックでエサを落とす、外敵を配置
- **表現アイディア**: 数百〜数千体が滑らかに群れる動き、光の透過表現
- **実装の勘所**: 実装は比較的容易でGPU化もしやすい。ただし「物理法則の可視化」という
  企画趣旨からはやや外れる（法則ではなくルールベースの創発）
- **評価**: 操作性◎ 見た目◎ 知名度○ 難易度: 低

### 8. ペンデュラム・アート（二重振り子・カオス理論）
- **物理的根拠**: 二重振り子の運動方程式（ラグランジアン導出の非線形連立ODE）、初期値
  鋭敏性（カオス）
- **知名度**: ○（「カオス理論」という言葉は知られているが、二重振り子自体はテレビで
  たまに紹介される程度）
- **操作アイディア**: 重りをドラッグして角度・勢いを与えてドロップ
- **表現アイディア**: 先端の軌跡をインクのように描画、幾何学模様の蓄積
- **実装の勘所**: ODEの数値積分（RK4等）は確立手法。`optics/tracer.ts` に近い
  「純粋関数で運動方程式を解く→描画層で消費」という構成がそのまま使える
- **評価**: 操作性◎ 見た目◎ 知名度○ 難易度: 低〜中

## 新規調査案（7件）

### A. 凸レンズ・凹レンズによる結像実験（幾何光学）
- **物理的根拠**: レンズの公式 `1/f = 1/a + 1/b`、屈折の法則。prism-sim の光学計算基盤
  （屈折・レイトレース）と同系統
- **知名度**: ◎（虫眼鏡・カメラ・老眼鏡など理科の定番単元）
- **操作アイディア**: 物体・レンズの位置をドラッグ、焦点距離をスライダーで変更
- **表現アイディア**: 光線の実際の経路と虚像/実像の作図をリアルタイム表示
- **実装の勘所**: 技術的難度は最も低い（prism-sim のレイトレース手法を概念的に転用できる）が、
  「またプリズムと同じ光学ネタか」という題材の重複感がある点に留意
- **評価**: 操作性◎ 見た目◎ 知名度◎ 難易度: 低

### B. シャボン玉・薄膜干渉の色（光学・界面科学）
- **物理的根拠**: 薄膜干渉の光路差 `2nt cosθ` による強め合い・弱め合い。膜厚で色が
  変わる仕組みは prism-sim の「波長→sRGB」変換ロジックと概念が近い
- **知名度**: ◎（シャボン玉の虹色模様は非常に身近）
- **操作アイディア**: 膜厚をドラッグで変える、傾ける、息を吹きかけて膨らませる
- **表現アイディア**: 3Dシャボン玉表面に干渉色をリアルタイムマッピング
- **実装の勘所**: 干渉計算自体は簡単だが、膜厚の流動的なムラ（対流）の表現に技術が要る
- **評価**: 操作性○ 見た目◎ 知名度◎ 難易度: 中

### C. BZ反応・反応拡散パターン（化学・自己組織化）
- **物理的根拠**: Belousov-Zhabotinsky反応やGray-Scott型の反応拡散方程式。渦巻き・
  迷路状パターンが自己組織的に生まれる
- **知名度**: △（現象の映像はテレビで見たことがある人もいるが、原理の知名度は低い）
- **操作アイディア**: クリックで反応の種を撒く、拡散係数・反応速度をスライダーで調整
- **表現アイディア**: 濃度場を色相にマッピングし、渦巻き模様が生成・崩壊する様子を描画
- **実装の勘所**: 反応拡散シミュレーションはGPU（フラグメントシェーダ）向きの定番アルゴリズム。
  他の候補と被らない、化学らしい題材
- **評価**: 操作性○ 見た目◎ 知名度△ 難易度: 中

### D. 虹の形成（一次虹・二次虹）
- **物理的根拠**: 球形の雨粒内での屈折＋内部反射＋屈折（デカルトの虹理論）、最小偏角
  約42°で強く見える
- **知名度**: ◎（非常に身近な自然現象）
- **操作アイディア**: 太陽の角度、観測者の視点をドラッグで変更
- **表現アイディア**: prism-sim同様に波長ごとの光路を計算し、実際に虹色が分離する様子を描画
- **実装の勘所**: prism-sim の tracer をほぼそのまま球形に応用できるため技術的難度は低いが、
  **prism-sim と題材が近すぎる**（光の分散つながり）ため、次の1本目としては優先度を下げるべき
- **評価**: 操作性○ 見た目◎ 知名度◎ 難易度: 低〜中（ただし題材の重複に注意）

### E. 交通流シミュレーション（渋滞学）
- **物理的根拠**: セルオートマトンベースの交通流モデル（Nagel-Schreckenbergモデル等）、
  「自然渋滞」（何もないのに車間が詰まって発生する渋滞）の再現
- **知名度**: ○（NHK「渋滞学」特集などで紹介された、日常的に体験する現象）
- **操作アイディア**: 道路上に車をドラッグで追加、速度・車間距離をスライダーで調整
- **表現アイディア**: 上から見た道路を車の密度に応じて色分け、渋滞の波が伝播する様子
- **実装の勘所**: 1次元CAモデルなら実装は容易。ただし「物理法則」というより交通工学モデル
- **評価**: 操作性○ 見た目○ 知名度○ 難易度: 低

### F. ライフゲーム／セルオートマトン（数理科学）
- **物理的根拠**: コンウェイのライフゲーム。生死ルールに基づくセルの遷移
- **知名度**: ○（有名な数理パズルだが、物理法則ではなく数理モデル）
- **操作アイディア**: セルをクリックでON/OFF、パターンをドラッグで配置
- **表現アイディア**: グリッドの生死パターンが波及・振動・移動する様子
- **実装の勘所**: 実装難度は最も低いが、「物理法則の可視化」という企画趣旨とはやや異なる
  （数理モデルであり物理・化学・宇宙科学ではない）ため優先度は低め
- **評価**: 操作性○ 見た目○ 知名度○ 難易度: 低（ただし企画趣旨との整合性に課題）

### G. メトロノームの同期現象（引き込み現象・非線形力学）
- **物理的根拠**: 複数のメトロノームが共通の台の上で徐々にリズムが揃う「引き込み現象」
  （非線形結合振動子の同期、蔵本モデル的な現象）
- **知名度**: △（YouTube等で有名な演示動画はあるが、日本の教科書での扱いは薄い）
- **操作アイディア**: メトロノームをドラッグで配置・数を増減、台の柔らかさを調整
- **表現アイディア**: 各メトロノームの振り子が徐々に同期していく様子をアニメーション
- **実装の勘所**: 強制振動・結合振動子の運動方程式は数値積分で解けるが、台との相互作用

- **評価**: 操作性○ 見た目○ 知名度△ 難易度: 中〜高

**総評**: 次の1本としては **8. 二重振り子** または **2. 磁力線と砂鉄** が最有力。
どちらも「知名度が高い」「見た目のインパクトが強い」「prism-sim の設計パターン
（純粋関数の計算層＋Three.js描画層＋Vitestでのユニットテスト）をそのまま踏襲できる」
という条件を満たし、かつ光学から離れた題材で次のアプリとしての多様性も確保できる。

**4位・5位について**: 雪の結晶（4位）と水面の波紋（5位）は3観点すべて◎・難易度中で拮抗して
おり、順位は僅差である。雪の結晶は「落下軌跡を描く」操作の独創性と、作った結晶が手元に残る
コレクション性で上回る。一方、水面の波紋は重ね合わせが厳密解で書けるぶん**物理的な誠実さの
コストが低い**（雪の結晶は (T, 過飽和度) → CAパラメータの現象論的な校正が避けられない）。
「独創的な体験」を取るなら雪の結晶、「物理の厳密さと確実性」を取るなら水面の波紋。

**設計上の一般則**: 4（雪の結晶）と6（炎色反応）の再検討から、この種のシミュレータでは
**「主題そのものは物理計算で出し、主題でない部分は現象論モデルと割り切って SPEC に明記する」**
という同じパターンで難易度が下がることが分かった。雪の結晶なら結晶形態が主題で対称性の強制は
不要な偽装、炎色反応なら発光色が主題で炎の形は現象論モデルでよい。prism-sim の
「虹色を7本の固定色で描くな」という規約は、**主題の偽装**を禁じているのであって、
すべてを第一原理から解くことを要求しているわけではない、と解釈するのが実務的である。
